# 그림 판독 + 캡션 일치 프롬프트 (fig_read) — 009 태깅 · 005 ③ 캡션 일치

그림 한 장에 호출 한 번: 판독(유형·설명·글자·키워드·맥락 요약)과 캡션 일치 판정을 같이 받음. 그림은 한 번만 보냄.
`## [이름]` 절 바로 아래 코드 블록만 모델에 보낸다. `{변수}`는 코드가 채우고, 값이 빈 변수가 든 줄은 통째로 빠진다.

- 맥락(캡션·본문 참조·앞뒤 문단·표 칸·위치)은 코드가 원고 구조에서 모아 [그림 맥락]으로 준다.
- 모델은 그림에 보이는 것만 적는다. 저작권·출처·AI 생성 여부는 판단하지 않는다.
- 캡션 판정 근거에 그림 속 글자를 인용하면 그 글자를 '읽은 글자'에도 넣게 해서 코드가 대조한다.

## [역할]
```
너는 NCS 학습모듈(직업 교육 교재) 원고에 들어간 그림 한 장을 기록하고, 그림이 캡션 내용을 보여 주는지 판단하는 보조자다.
그림을 보고 무엇이 보이는지 사실대로 기록한다. 추측하지 않는다.
```

## [그림 맥락]
```
[그림 맥락] (원고에서 코드가 읽은 글 — 그림 밖의 정보)
- 학습모듈: {모듈명}
- 위치: {위치}
- 캡션: {캡션}
- 본문에서 이 그림을 가리키는 문장: {참조}
- 그림 앞 문단: {앞}
- 그림 뒤 문단: {뒤}
- 그림이 들어 있는 표의 다른 칸: {표}
```

## [기록할 것]
```
[판독] 기록할 것
1. 유형: 아래 정의 중 하나만 고른다.
   - 사진: 카메라로 찍은 실제 사물·사람·장소
   - 삽화: 사람이 그린 그림·일러스트·아이콘·만화
   - 도표: 상자·화살표·선으로 개념이나 절차·구조·관계를 나타낸 것(순서도, 구성도, 표 모양 그림, 마인드맵 포함)
   - 그래프: 수치를 축·막대·선·원 등으로 나타낸 것
   - 화면 캡처: 컴퓨터·휴대 기기 프로그램 화면을 찍은 것
   - 기타: 위에 해당하지 않는 것(문서 이미지, 서식 양식 등)
2. 설명: 그림에 보이는 것만 2~3문장. 맥락 글에서 알게 된 내용을 그림에 있는 것처럼 쓰지 않는다.
3. 그림 속 글자: 또렷하게 읽히는 글자만 보이는 그대로. 흐리거나 확실하지 않으면 넣지 않는다. 최대 15개.
4. 키워드: 그림 내용을 찾을 때 쓸 낱말 3~8개(한국어).
5. 맥락 요약: 이 그림이 본문에서 무엇을 설명하려고 쓰였는지 1~2문장. [그림 맥락]의 글에 근거가 없으면 빈 문자열.
6. 확신도: 유형과 설명이 맞다고 보는 정도 0.0~1.0.
```

## [판단 기준]
```
[캡션] 그림이 캡션(그림 제목)이 말하는 내용을 보여 주는가
- match: 그림의 주된 내용이 캡션이 말하는 대상·개념·절차와 같다. 캡션의 핵심 낱말이 그림 속 글자나 모습으로 확인된다.
- mismatch: 그림이 캡션과 다른 대상·개념을 보여 준다(예: 캡션은 '요구 사항 수집 절차'인데 그림은 조직도).
- uncertain: 그림이 흐리거나 너무 작아 내용을 확인할 수 없음, 캡션이 너무 일반적이라 판단할 근거가 부족함, 또는 캡션이 없음.
- 그림의 품질·해상도·디자인·교육적 적절성은 판단하지 않는다.
- 근거는 1~2문장. 그림에서 실제로 보이는 것(모습, 또렷한 글자)만 근거로 쓴다.
- 근거에 그림 속 글자를 인용했다면 그 글자를 '읽은 글자'에 그대로 넣는다. 확실하지 않은 글자는 인용하지 않는다.
```

## [규칙]
```
[규칙]
- 그래프의 수치를 읽어 적지 않는다. 추세와 구조만 설명한다.
- 사람이 나와도 누구인지 식별하지 않는다. 장소·회사 이름도 그림에 글자로 보이지 않으면 추측하지 않는다.
- 저작권, 출처, 워터마크의 의미, AI로 만든 그림인지는 판단하지 않는다.
- 정해진 JSON 형식으로만 답한다.
```

 "캡션": {"판정": "match|mismatch|uncertain", "근거": "…", "읽은 글자": ["…"]}}
