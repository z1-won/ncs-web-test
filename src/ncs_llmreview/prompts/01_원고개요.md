# 01 원고 개요 — 주제·분량 (task `summary`, 1차 읽기)

체크리스트에 직접 있는 항목은 아니지만, 이 결과를 2차 task의 `{원고_요약}`과 이미지 RAG [1]에서 다시 씀.
**글자 수·비율은 코드가 계산해서 넣는다.** LLM은 숫자를 세지 않고, 숫자를 보고 내용이 그럴 만한지만 판단한다.

이 task는 [규칙] 5·6(인용·수정 문장)을 쓰지 않고 출력 형식도 다르므로, 00_공통의 [역할]·[원고 정보]만 붙이고 아래 [규칙]·[출력 형식]을 쓴다.

## [체크 항목]

```
[체크 항목]
원고 전체의 주제를 요약하고, 부분별 분량이 내용에 비해 지나치게 많거나 적은 곳을 찾는다.
(참고: 기타 ⑥ "학습 단원별로 필요 지식과 수행 내용의 비율이 3:7이 되는가? 최소한 5:5 정도는 되어야 함.")
```

## [판단 기준]

```
[판단 기준]
- 입력의 "분량" 표는 코드가 센 글자 수(공백 제외)와 비율이다. 숫자는 그대로 믿고 다시 세지 않는다.
  "평균_대비"는 그 부분 전체 글자 수 ÷ 학습 내용 평균 글자 수다.
- "후보": true 인 부분만 지적할 수 있다. 후보는 코드가 숫자로 고른 것이다. 후보가 아닌 부분은 요약에만 쓴다.
- 후보라도 분량 차이만으로 지적하지 않는다. 다음일 때만 지적한다.
  · 분량 과다: 다른 부분보다 훨씬 길고(표의 "평균 대비"가 큼), 앞부분 내용을 보면 학습 목표와 직접 상관없는 배경·역사·일반론이 많다.
  · 분량 부족: 다른 부분보다 훨씬 짧아, 학습 목표를 달성하기에 내용이 모자라 보인다.
  · 서론 과다: 학습 내용 앞의 도입·개요 설명이 본문에 비해 길다.
  · 비율 불균형: 필요 지식이 수행 내용보다 많다(5:5를 넘음). 코드 표의 "필요지식_비율"을 근거로 쓴다.
- 학습 내용이 원래 어려워서 긴 것(학습 목표가 많거나 복잡함)은 지적하지 않는다.
```

## [입력] (user)

코드가 만든다. 각 부분의 "앞부분"은 처음 300~500자.
"후보"는 코드가 정함 — 초안 기준: 평균_대비 ≥ 1.8 또는 ≤ 0.5, 필요지식_비율 > 0.5, 도입 글자 수가 학습 내용 평균의 0.5배 초과. 숫자는 실험하며 조정.

```json
{
  "목차": ["학습 1 ○○하기", "1-1 ○○ 파악", "1-2 ○○ 분석", "학습 2 ○○하기", "2-1 ○○ 설계"],
  "분량": [
    {"부분": "도입", "글자": 3100, "평균_대비": 0.3, "후보": false},
    {"부분": "1-1", "필요지식_글자": 4200, "수행_글자": 6100, "필요지식_비율": 0.41, "평균_대비": 1.0, "후보": false},
    {"부분": "1-2", "필요지식_글자": 9800, "수행_글자": 2100, "필요지식_비율": 0.82, "평균_대비": 1.9, "후보": true}
  ],
  "부분": [
    {"부분": "1-1", "학습_목표": ["○○을 파악할 수 있다."], "앞부분": "…"},
    {"부분": "1-2", "학습_목표": ["…"], "앞부분": "…"}
  ]
}
```

## [규칙]

```
[규칙]
1. 지적할 부분이 없으면 "지적": [] 를 출력한다. 빈 목록도 올바른 답이다.
2. "부분"은 입력의 부분 번호(예: "1-2")를 그대로 쓴다.
3. "근거"에는 입력의 숫자나 앞부분 내용을 들어 한 문장으로 쓴다.
4. 요약은 입력에 있는 내용만으로 쓴다. 없는 내용을 지어내지 않는다.
5. 아래 형식의 JSON만 출력한다.
```

## [출력 형식]

```
{"주제": "원고 전체 주제 1~2문장",
 "학습별_요약": [{"부분": "학습 1", "요약": "1문장"}],
 "지적": [{"부분": "1-2", "문제": "분량 과다|분량 부족|서론 과다|비율 불균형", "근거": "한 문장", "제안": "무엇을 줄이거나 늘릴지 한 문장"}]}
```

## 메모
- 원고가 길어 "앞부분"만으로 부족하면 학습마다 따로 요약(map)한 뒤 그 요약들로 다시 이 프롬프트를 돌림(reduce).
- 비율 불균형 판정 자체는 엔진(기타 ⑥ `ratio.py`)이 함. 여기서는 **왜 그런지**(무엇이 길어서인지) 설명을 붙이는 용도.
