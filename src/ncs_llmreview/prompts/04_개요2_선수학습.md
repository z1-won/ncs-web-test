# 04 개요 ② 선수학습 (task `overview2_prereq`)

보내는 것: 학습모듈의 개요 '선수학습' 항목들.
개수(5개 이내)는 엔진(`ncs_overview/rules/prerequisites.py`), 분류 번호·코드 형식(개요 ③)·수준(개요 ④)도 엔진 몫 → LLM은 **"구체적인 과목명·학습모듈명(또는 NCS 능력단위)인가"** 만 봄.

## [체크 항목]

```
[체크 항목] 학습모듈의 개요 ②
'선수학습'에서 구체적인 과목명, 학습모듈명(또는 NCS 능력단위)을 5개 이내로 제시하였는가?
(개수는 이번 판단에 넣지 않는다.)
```

## [판단 기준]

```
[판단 기준]
선수학습 항목 하나하나를 본다.
- 지적하지 않음: 실제로 있을 법한 과목명(예: 일반화학, 회계원리), NCS 학습모듈명이나 능력단위명(코드가 붙었든 아니든).
- 지적함:
  · 막연한 분야: 과목이나 모듈이 아니라 넓은 분야·능력을 적었다. (예: 기초 지식, 관련 이론, 컴퓨터 활용 능력, 실무 경험)
  · 과목 아님: 자격증, 경력, 태도, 도구 이름 등 학습 과목이 아닌 것을 적었다.
  · 무관: 이 학습모듈(원고 정보의 학습모듈·분야·목표)을 배우기 전에 필요한 내용으로 보기 어렵다.
- 과목명이 실제로 있는지 확신할 수 없으면 지적하지 않는다(무관은 분명할 때만).
- 대학이나 직업교육에서 강좌 이름으로 쓰이는 말(예: 경영전략, 소프트웨어공학, 조직관리)은 과목명으로 본다.
  '~ 지식', '~ 능력', '~ 경험', '~ 이해', '관련 이론'처럼 끝나 범위만 말하는 것은 막연한 분야다.
- 선수학습이 한 문단에 쉼표로 이어져 있으면 항목마다 따로 판단한다. "인용"에는 문제가 있는 항목 하나만 넣고,
  "수정 문장"은 그 항목만 고친 문단 전체로 쓴다.
- 학습모듈 코드가 붙어 있으면 학습모듈명으로 보고 지적하지 않는다. 코드가 맞는지는 이번 판단에 넣지 않는다.
```

`{문제_종류}` = `막연한 분야` | `과목 아님` | `무관`

"수정 문장"은 항목 한 줄. 구체적인 이름을 모르면 "○○ 관련 과목명(예: ○○개론)"처럼 비워 둔다. 없는 모듈 코드를 지어내지 않는다.

## [찾을 곳] — 슬라이스 ①·②(원고를 통째로·고정 길이로 보낼 때)만 붙임. ③은 코드가 이미 그 부분만 잘라 보냄

```
[찾을 곳]
'학습모듈의 개요' 표에서 '선수학습' 칸의 문단만 검수 대상이다.
```

## [예시] — 기본 예시(직접 만든 문장)

```
[예시]
(학습모듈: 재무제표 작성, 분야: 회계)
지적함
- "회계 기초 지식"         → 문제: 막연한 분야 / 수정 문장: "회계 관련 과목명(예: 회계원리)"
- "전산회계 자격증"        → 문제: 과목 아님 / 수정 문장: "○○ 관련 과목명 또는 학습모듈명"
- "조리 실무"              → 문제: 무관 / 수정 문장: "○○ 관련 과목명 또는 학습모듈명"
지적하지 않음
- "회계원리"
- "전표 관리(LM○○○○○○○○○○_○○v○)"   (학습모듈명 + 코드)
- "결산 관리"                      (능력단위명 — 코드 유무는 개요 ③에서 엔진이 봄)
```
