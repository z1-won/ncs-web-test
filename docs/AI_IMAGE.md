# 이미지 AI 보완 (REQ-02-006)

정의서의 '이미지·도식 AI 생성 및 수정 보완' 가운데 표기, 현황, 유의 안내와 화질 보정의 연결을 맡습니다. 화면은 메뉴 **이미지 › 이미지 AI 보완**(`/ai-image`)입니다.

| 정의서 항목 | 상태 | 어디 |
|---|---|---|
| ① AI 생성 | 도표·표·그래프(화면 `/ai-generate`), 만든 그림의 DB 등록과 닮은 그림 대조 | `ncs_aiimage/diagram.py`, `draw.py`, `generate.py`, `ncs_service/images/image_generate.py`. 사진·삽화는 서버에 올리는 공개 모델로 만듭니다(`prompt.py`, `imagegen.py`, 화면 `components/PictureMaker.jsx`). 엔진은 기본 꺼짐이고 실제 모델로는 아직 돌려 보지 않았습니다 |
| ② AI 수정 보완 | 화질 보정만 | `ncs_upscale`(업스케일링 화면). 보정한 그림을 이미지 저작권 DB에 AI 활용 정보와 함께 올립니다. 내용 수정은 없습니다 |
| ③ 표기 문구 자동 삽입 | 구현 | `ncs_core/figures.py`(줄 쓰기), `ncs_aiimage/marking.py`(원고에 넣기) |
| ④ 생성형 AI 결과물 현황 자동 작성 | 구현(xlsx) | `ncs_aiimage/results.py` |
| ⑤ 프롬프트 유의 안내 | 구현 | `ncs_aiimage/notice.py`, 화면에서 확인해야 내려받기가 열립니다 |

## 도표·표·그래프 만들기 (① AI 생성의 일부, 2026-11-24, 그래프와 DB 연결 2026-11-25)

집필자가 쓴 문단을 바탕으로 도표, 표, 그래프를 만듭니다. 생성형 AI(글)는 그림이 아니라 **명세**(JSON)를 쓰고, 그림은 서버의 코드가 그립니다(`ncs_aiimage/draw.py`). 표기 예 1(집필진이 내용을 작성하고 AI로 이미지를 만든 경우)에 해당합니다.

| 종류 | kind | 모양 |
|---|---|---|
| 순서 | `sequence` | 2~8칸, 5칸까지는 가로 한 줄, 그보다 많으면 세로 |
| 순환 | `cycle` | 3~6칸, 마지막에서 처음으로 |
| 구성 | `structure` | 맨 위 칸(`root`) 아래 2~6갈래, 갈래마다 글 6줄까지 |
| 비교 | `compare` | 2~4열, 열마다 글 1~6줄 |
| 표 | `table` | 2~6열, 1~10행. PNG 말고도 한글 프로그램에 붙여 넣을 html·tsv로 받을 수 있음 |
| 막대 그래프 | `bar` | 범주 2~12개, 계열 1~4개. 값은 0 이상 |
| 꺾은선 그래프 | `line` | 범주 2~12개, 계열 1~4개 |
| 원 그래프 | `pie` | 범주 2~8개, 계열 1개. 비율은 값에서 계산해 적음 |

그래프 명세: `{kind, title, unit, categories: [범주…], series: [{name, values: [수…]}]}`. 요청의 `kind`에 `diagram`(순서·순환·구성·비교)이나 `graph`(막대·꺾은선·원)를 주면 그 유형 안에서 생성형 AI가 고릅니다.

검사는 둘입니다(`ncs_aiimage/diagram.py`).

- **모양**(`read_spec`): 칸 수, 글 길이, 겹치는 이름. 어기면 그릴 수 없습니다.
- **근거**(`grounding`): 명세의 글이 문단·수행준거에 있는 말인지 봅니다. 글에 없는 낱말, 글에 없는 수, 글에 없는 영문, 상표·상품명을 지적합니다. 생성형 AI가 낸 후보는 지적이 하나라도 있으면 쓰지 않습니다. 사람이 고친 명세에는 알림으로만 보입니다(집필자가 쓴 말이므로 막지 않습니다).
  그래프의 값은 두 가지를 봅니다. 문단에 적힌 수인가, 그리고 그 수가 같은 문장에서 **그 범주 이름 뒤에, 다른 범주 이름을 사이에 두지 않고** 적혀 있는가. 뒤의 것이 값이 뒤바뀐 후보(2024년에 2025년의 값)를 잡습니다. 합계나 비율처럼 계산한 값은 문단에 적혀 있지 않으면 떨어집니다. '범주 뒤에 수'가 아닌 글(수가 먼저 나오는 문장, 표처럼 늘어놓은 글)은 맞는 값도 지적될 수 있습니다.

- **빠진 내용**(`omissions`): 근거 검사의 반대쪽을 어림합니다. 문단에 '쓰지 않는다', '금지', '주의' 같은 말이 든 토막이 있는데 명세에 없거나, 문장의 낱말이 명세에 거의 쓰이지 않으면 알립니다. 알림일 뿐이고 후보를 떨어뜨리지 않습니다.

낱말 대조는 형태소 분석이 아니라 어림입니다(조사·어미를 떼어 가며 글에 있는지 봄). '절차', '구분', '내용' 같은 틀을 이루는 말은 글에 없어도 받습니다.

그림은 놓을 폭(mm, 기본 150)에서 300 DPI로 냅니다. 색은 회색 단계만 씁니다. 같은 명세는 같은 파일이 됩니다. 제목(`title`)은 그림 안에 그리지 않습니다. 원고의 그림 제목 줄에 쓸 글입니다.

글꼴은 KoPub 돋움체(Medium, Bold)를 먼저 찾습니다. `fonts/` 폴더(git 제외)나 `NCS_FONT_DIR`에 두고, 없으면 시스템의 한글 고딕을 씁니다. 하나도 없으면 그리기는 503을 냅니다.

생성형 AI를 쓸 수 없으면(키나 외부 전송 승인 없음) 후보를 만들지 않습니다. 명세를 직접 적어 그리는 것은 그대로 됩니다. 허용 작업은 `image_generate_spec`, 모델은 `LLM_MODEL_AIIMAGE`(없으면 `LLM_MODEL`)입니다.

화면은 메뉴 **이미지 › 이미지 AI 생성**(`/ai-generate`)입니다(`docs/WEB.md`). 이미지 추천의 결과에서 [이 문단으로 이미지 AI 생성]을 누르면 문단과 수행준거 글을 넘겨받습니다(주소에 싣지 않습니다). 아직 없는 것: 사진·삽화, 생성형 AI 결과물 현황과의 자동 연결, 유용성 문항.

### 이미지 저작권 DB 연결 (`ncs_service/images/image_generate.py`, 데이터베이스가 있는 서버만)

- **닮은 그림 대조**(`similar`): 그린 그림을 DB의 그림과 견줍니다. ① 같은 파일(sha256) ② 지각 해시(pHash 64비트)의 해밍 거리 10 이하 ③ 임베딩을 켠 서버에서는 코사인 유사도 0.9 이상. 지각 해시는 `image_phashes`(마이그레이션 `023_image_phashes`)에 두고, 없는 그림은 대조할 때 300장씩 채웁니다(응답의 '남은 그림'이 0이 아니면 일부만 견준 것). 집필진에게는 기관이 확정해 추천에 나오는 그림하고만 견줍니다. 기준값 10과 0.9는 실제 그림으로 맞춘 값이 아닙니다. 틀이 같은 도표(같은 칸 수의 순서도)는 내용이 달라도 닮은 그림으로 나올 수 있습니다 — 알림이지 판정이 아닙니다.
- **등록**(`register`, 에디터·직능연): 서버가 명세로 다시 그린 PNG를 이미지 레코드로 적재합니다(`image_db.load_records`). 종류는 도표·표 → `table`(DB의 '도표'), 그래프 → `graph`. 분류는 집필진 제작, AI 활용 유형 1(집필진 작성 내용 기반 AI 생성)·도구·일자. 직접 적어 그린 그림은 AI 활용 정보를 적지 않습니다. 모듈 코드를 주면 번호와 함께 수록 위치를 남깁니다. 권리 귀속과 재사용 범위는 정하지 않으므로 기관이 확정하기 전에는 추천에 나오지 않습니다.
- **Recall@k 재기**: `scripts/probe/similar_recall.py`가 DB의 그림을 줄임·JPEG 재저장·흑백·가장자리 자름·밝기 바꿈으로 바꿔 넣고 원래 그림이 상위 k에 나오는 비율을 찍습니다. 2026-11-25, 점검용 DB의 그림 8장, 지각 해시만: 40건 가운데 39건(97.5%), 놓친 1건은 가장자리 5% 자름. 그림이 8장뿐이라 이 수치로 기준을 정할 수는 없습니다. 뜻이 비슷한 다른 그림을 찾는 일은 정답 세트가 있어야 잽니다.

### 사진·삽화 (2026-11-25)

외부 서비스의 약관(출판, 권리 양도)이 정해지지 않아, **서버에 직접 올리는 공개 모델**로 만듭니다. 외부로 보내는 것이 없고 서비스 약관이 없습니다. 모델의 라이선스만 봅니다.

- **엔진**(`ncs_aiimage/imagegen.py`): 기본 꺼짐. `NCS_IMAGEGEN_ENGINE=diffusers`와 `requirements/imagegen.txt` 설치로 켭니다. 기본 모델은 `black-forest-labs/FLUX.1-schnell`(모델 카드: Apache 2.0, 상업 목적 허용)이고 `NCS_IMAGEGEN_MODEL`로 바꿉니다. 다른 모델을 쓰면 그 모델의 라이선스를 먼저 확인합니다. 그림은 1024×768(가로), 768×1024(세로), 1024×1024 가운데 하나로, 한 번에 4장까지 만듭니다.
- **프롬프트**(`ncs_aiimage/prompt.py`): 생성형 AI(글)가 문단에서 장면 후보(한국어, 영어)를 최대 3개 씁니다(허용 작업 `image_generate_prompt`). 집필자가 한국어 장면을 고치면 그 장면만 다시 영어로 옮깁니다. 모델에 보내는 글은 영어 장면 + 유형별 화풍 + **고정 제한 문구**(얼굴이 드러난 사람 없음, 글자·로고·워터마크 없음)입니다.
- **프롬프트 검사**: 얼굴이 드러나는 그림을 청하는 말(얼굴, 표정, portrait 등), 상표·상품명, 특정 작가·작품의 화풍을 따르라는 말이 있으면 만들지 않습니다. 뒷모습, 멀리 있는 모습, 손은 됩니다. 글자를 청하는 말은 알림만 합니다. **실존 인물의 이름은 사전이 없어 잡지 못합니다.** 만든 그림에 얼굴이 나왔는지도 자동으로 보지 않습니다 — 사람이 확인합니다.
- **받기 전 확인**(`image_generate.inspect`): 놓을 폭에서의 DPI(1024px은 150mm에서 173 DPI, 300 DPI가 되는 폭은 86mm), DB가 있으면 닮은 그림. 그림 속 글자(OCR) 확인은 아직 잇지 않았습니다.
- **화면**: 유형에서 사진이나 삽화를 고르면 [장면 만들기] → 장면을 골라 고침 → [그림 만들기] → 한 장을 골라 확인 → 받기. 받기 전에 사람이 세 가지를 확인해야 내려받기와 DB 올리기가 열립니다(얼굴이 드러난 사람 없음, 읽히는 글자·로고 없음, 실제 장비·작업과 다르지 않음). 엔진이 꺼진 서버에서는 장면과 모델에 보낼 글까지만 만듭니다.
- **표기**: 문단을 바탕으로 만들면 표기 예 1, 문단 없이 주제만 주면 표기 예 4(AI 창작). 예 4의 출처 줄은 F08과 맞는지 확인이 필요합니다.
- **실제 모델로 돌려 보지 않았습니다.** `scripts/probe/imagegen_probe.py`가 모델을 올리고 그림을 만들어 걸린 시간을 찍습니다. FLUX.1 schnell은 큰 모델이라 개발용 컴퓨터의 메모리로 올라가는지부터 확인해야 합니다.
- AI가 만든 그림에 저작권이 인정되는지, 그 권리를 정부로 넘길 수 있는지는 모델 라이선스와 별개의 법률 문제입니다. 기관의 확인이 필요합니다.

### 실제 원고로 재기

`scripts/probe/manuscript_paragraphs.py`가 원고(hwp·hwpx)에서 문단을 뽑고(절반은 순서·종류·수치가 있을 법한 문단, 절반은 그 밖), `diagram_probe.py --report 판정.tsv`가 후보마다 한 줄을 씁니다. '사람 판정' 칸에 `맞음 | 틀림 | 그릴 것 없음`을 적고 `--tally`로 세면 **검사를 통과했지만 쓸 수 없는 후보의 비율**이 나옵니다. 문단을 외부 생성형 AI로 보내는 일이므로 원고를 보내도 되는지 정한 뒤에 돌립니다. 아직 실제 원고로 돌린 결과는 없습니다.


실제 생성형 AI로 돌린 결과(2026-11-24, `scripts/probe/diagram_probe.py`, 예시 문단 6개): 그릴 수 있는 문단 5개에서 후보 6개가 모두 통과했고, 정의만 있는 문단 1개는 모양 검사에서 떨어졌습니다. 글에 없는 사실이 들어간 후보는 없었습니다. 처음에는 '정하고 → 정함', '종류에 → 종류별'처럼 줄여 쓴 말 때문에 2개가 떨어져 낱말 대조를 고쳤습니다. 표 후보 하나가 '물 소화기는 쓰지 않는다'를 빠뜨려 빠진 내용 알림과 프롬프트 규칙을 더했습니다. 프롬프트를 고친 뒤의 결과는 아직 보지 않았습니다. 문단이 지어 쓴 6개뿐이라 실제 원고 문단에서의 통과 비율은 모릅니다.

## 표기 (③)

그림 한 개의 표기는 세 줄입니다(F14 집필 양식, F08 AI 도구 사용 표기 예).

```
출처: 집필진 제작(2026)                       ← 원고에 있던 줄 그대로
ChatGPT를 활용하여 수정 보완함. 2026. 7. 20.  ← 넣는 줄
[그림 1-1] 생산 설비 주요 구성 요소           ← 원고에 있던 줄 그대로
```

- 넣는 줄은 `ncs_core.figures.ai_line(도구, 방식, 일자)`가 만듭니다. 방식은 `generated`(생성함)와 `modified`(수정 보완함) 둘입니다. 조사 '을/를'은 도구 이름의 끝소리로 정합니다.
- 넣는 자리는 캡션 문단 바로 앞입니다. 새 문단의 모양은 출처 줄을 따르고, 출처 줄이 없으면 캡션을 따릅니다.
- **출처 줄은 넣지 않습니다.** 없는 출처를 지어낼 수 없어서입니다. 화면이 '출처 줄 없음'으로 알려 줍니다.
- 이미 AI 활용 줄이 있는 그림에는 넣지 않습니다.
- hwpx 원고만 됩니다. 올린 원고는 바꾸지 않고 사본을 돌려줍니다. 넣은 줄 말고는 문단 글이 같고, 그림 파일과 다른 항목은 바이트 그대로입니다.
- 도구 이름에는 쉼표를 쓸 수 없고, 마침표는 판 번호의 숫자 사이(`ChatGPT 6.0`)에만 쓸 수 있습니다. 읽는 쪽(`parse_ai_mark`)도 이번에 숫자 사이의 마침표를 이름의 일부로 읽게 고쳤습니다(전에는 `ChatGPT 6.0을 활용하여`에서 도구를 `0`으로 읽었습니다).
- 읽은 문서의 구역은 파일의 구역과 다를 수 있습니다(`normalize_sections`가 앞부분과 본문으로 다시 나눕니다). 넣을 자리는 문서 전체에서 몇 번째 문단인지로 찾고, 파일의 문단 수가 읽은 것과 다르면 아무것도 넣지 않습니다.

검수 쪽에서는 필요 지식 ⑧이 같은 읽기로 AI 활용 줄의 꼴과 순서를 판정합니다(`docs/CONSISTENCY_REVIEW.md` 5.21).

## 현황 (④)

원고에서 AI 활용 줄이 붙은 그림을 모아 서약서 붙임 양식의 칸으로 만듭니다: `순번 | 결과물 명 | 학습모듈 해당 쪽수 | 활용 AI | 비고`.

- 결과물 명은 `그림 1-1 그림명`, 비고에는 방식과 일자를 적습니다.
- 쪽수는 출력본 PDF를 함께 올렸을 때만 `p.12`로 적습니다. 같은 그림 번호가 여러 쪽에 있으면 모두 적고 비고에 알립니다.
- 파일은 xlsx입니다. 한글 양식(hwpx)으로는 만들지 않습니다. 서약서 붙임에 옮겨 적어야 합니다.

## 화질 보정과의 연결 (②)

- 업스케일링 화면의 제안본 내려받기에 **제안본에 AI 활용 표기 넣기**가 있습니다(기본 켜짐). 보정한 그림의 캡션 위에 `waifu2x를 활용하여 수정 보완함. 오늘 날짜` 줄을 넣습니다. 도구 이름은 모델에 따라 `waifu2x` 또는 `Real-ESRGAN`입니다.
- **이미지 저작권 DB에 올리기**(에디터와 직능연, 데이터베이스가 있을 때): 원본과 업스케일본, 수록 위치, AI 활용 정보(활용 유형 3 '기존 이미지 보정', 수정 보완, 도구, 일자, 원본 출처 = 원고의 출처 줄)를 이미지 레코드로 적재합니다. 기관이 확정한 그림의 권리 정보는 바꾸지 않습니다. 분류 체계와 재사용 범위는 정하지 않습니다.
- 캡션을 찾지 못한 그림은 표기도 DB 등록도 건너뛰고 그 수를 알려 줍니다.

## API

| 경로 | 내용 |
|---|---|
| `GET /api/ai-image/notice` | 유의 안내(근거와 항목) |
| `POST /api/ai-image/figures` | `manuscript`(hwp, hwpx) + `print_copy`(PDF, 선택) → 그림 목록, 이미 있는 AI 표기, 쪽 |
| `POST /api/ai-image/preview` | + `marks` → 그림마다 표기 세 줄과 현황 줄 |
| `POST /api/ai-image/marked` | `manuscript`(hwpx) + `marks` → 표기를 넣은 원고 사본. 요약은 `X-Ai-Summary` |
| `POST /api/ai-image/results` | `manuscript` + `print_copy` + `marks` → 현황 xlsx |
| `POST /api/ai-image/source` | `manuscript`(hwpx) + `key` + `credit` → 출처 줄이 없는 그림에 출처 줄을 넣은 사본(이미지 추천이 씀, `docs/RECOMMEND.md`) |
| `POST /api/uploads/{token}/proposal` | `ai_mark=true`, `ai_date`(선택)를 주면 제안본에 표기를 함께 넣음 |
| `POST /api/uploads/{token}/pictures/register` | 보정한 그림을 이미지 저작권 DB에 올림 |

`marks`: `[{"key": 그림 목록의 key, "tool": "ChatGPT", "mode": "generated" | "modified", "date": "YYYY-MM-DD"}]`. 올린 파일은 읽는 동안만 임시 폴더에 두고 지웁니다. 데이터베이스에 남기는 것은 DB 등록을 눌렀을 때의 이미지 레코드뿐입니다.

## 검증 (2026-11-23)

| 정의서 기준 | 결과 | 표본 |
|---|---|---|
| 표기 문구 삽입 100% | 129개 중 129개 삽입 | `samples/`의 실제 원고 5권(51, 17, 17, 17, 27그림), 표기가 없는 그림 전부에 넣음 |
| 생성함/수정 보완함 구분 오차율 0.5% 이내 | 틀림 0 / 129, 줄 단위로는 0 / 150 | 위 원고에서 번갈아 넣고 다시 읽음. 줄 단위는 도구 15 × 방식 2 × 날짜 5 |
| 결과물 현황표와 원고 표기 일치 100% | 현황 쪽 지적 0건 | 합성 원고 1권: 표기를 넣은 원고와 그 현황으로 권리 증빙 점검(`ncs_rights`)을 돌림 |

한계

- 넣은 원고를 **한글 프로그램에서 열어 보지는 못했습니다.** 읽기(이 저장소의 hwpx 읽기)로만 확인했습니다. 글자 모양과 쪽 넘김은 한글에서 확인해야 합니다.
- 삽입과 구분의 표본은 넣은 것을 같은 저장소의 읽기로 다시 읽은 것입니다. 사람이 적은 표기를 읽는 정확도와는 다른 값입니다.
- 현황 일치는 합성 원고 1권입니다. 쪽수는 실제 출력본으로 재지 않았습니다.
- 유용성(Likert)과 유사성 Recall@k는 생성 기능이 없어 잴 것이 없습니다.

## 원본 이용 조건 확인 (REQ-02-006 ⑥)

출처 줄에 적힌 공공누리 유형을 읽어(`ncs_core.source_line.kogl_terms`) 조건에 맞게 막거나 알립니다. 유형이 적혀 있지 않은 그림은 판단하지 않습니다(추측하지 않음).

| 원본 | 업스케일(화질 보정) | AI 활용 표기 넣기 | 결과물 현황 |
|---|---|---|---|
| 제3·4유형(변경금지) | 목록에 '업스케일 제외'로 보이고 실행을 거절 | 고를 수 없고, 요청에 섞여 오면 빼고 '변경금지 원본 제외'로 알림 | 이미 AI 표기가 있으면 비고에 '변경금지 원본 — 확인 필요' |
| 제2·4유형(상업적 이용금지) | 조건을 알림 | 넣음 | 비고에 '원본 공공누리 제N유형: 비상업적 이용만 가능' |
| 그 밖의 유형 | 그대로 | 넣음 | 비고에 '원본 공공누리 제N유형' |

검증 기준 '변경금지(제3·4유형) 원본의 수정 보완 0건'은 이 도구를 거친 경로에만 해당합니다. 이용허락 범위에 변경이 허용되지 않은 그 밖의 자산(공공누리가 아닌 것)은 출처 줄만으로 알 수 없어 다루지 않습니다 — 이미지 저작권 DB의 권리 정보와 연결해야 합니다.
