# 권리 증빙 제출 현황 점검 (REQ-02-014)

원고의 그림과 제출 서류를 대조해 빠진 권리 증빙을 찾습니다. 기준은 「NCS PoC 과업 안내」(요구사항정의서 V0.23) REQ-02-014,
원고 집필 계약서(F07), 사진·삽화 제작 계약서(F06), AI 도구 사용 표기 예(F08), 생성형 AI 결과물 집필자 서약서(F09)입니다.
코드는 `ncs_rights`(서류 읽기·대조, `pages.py`는 출력본의 쪽), `ncs_core/figures.py`(원고의 그림 읽기), `ncs_service/rights_link.py`(이미지 저작권 DB 연결),
평가는 `tests/eval_rights.py`.

## 쓰는 법

화면: 메뉴의 **권리 증빙 점검**(`/rights`). 데이터베이스 없이도 됩니다.

```bash
python -m ncs_rights 원고.hwpx 계약서붙임.hwp 제작목록.hwp 서약서.hwpx \
    --first-review 2026-10-01 --submitted 2026-10-20 --transfer-author --transfer-maker --pledge --portrait none \
    --print 출력본.pdf --xlsx 현황표.xlsx
```

## 입력

| 입력 | 내용 |
|---|---|
| 원고 | hwpx 또는 hwp. 그림 캡션 `[그림 N-M] 그림명`과 그 위의 `출처:` 줄, AI 활용 줄을 읽음 |
| 제출 서류 | 작성한 한글 양식(hwp·hwpx) 여러 개. **파일 이름과 무관하게 안에 든 표의 머리 글로 양식을 알아봄** — 계약서 한 파일에 붙임이 여러 개 있어도 됨 |
| 1차 검토일, 제출일 | 수록 현황 목록의 제출 기한(1차 검토 이후 4주, 원고 집필 계약서 제5조 1항) 계산용 |
| 서명 서류 제출 여부 | 집필자 양도 동의서, 제작자 양도 동의서, AI 서약서 — 표가 아니라 서명 문서라 파일에서 읽지 못해 직접 표시 |
| 초상권 | 확인하지 않음 / 인물이 든 사진 없음 / 동의서 제출됨. 인물 포함 여부는 그림을 봐야 알므로 자동 판정하지 않음 |
| 출력본 PDF (선택) | 그림 캡션이 놓인 쪽을 읽어 생성형 AI 결과물 현황의 쪽수와 대조하고, 현황표에 그림마다 쪽을 실음. 글자를 뽑을 수 없는 PDF(스캔본)는 읽지 못함 |

읽는 표:

| 양식 | 알아보는 머리 글 | 읽는 것 |
|---|---|---|
| 사진·삽화 수록 현황 목록 (F07 붙임 2) | 시각적 자료 제목, 저작물 제작 방식 | 그림 번호·제목, ✓가 놓인 제작 방식 칸(사진/삽화 구분 포함), 학습모듈명 |
| 사진·삽화 제작 목록 (F06 붙임 1) | 저작물명, 자료 유형 | 그림 번호·제목, 사진/삽화 |
| 지식재산권 이용허락 동의서 (F07 붙임 3) | 저작물 제목, 출처 | 저작물 제목, 출처, 활용 학습모듈명 |
| 생성형 AI 결과물 현황 (F09 붙임) | 결과물 명, 활용 AI | 결과물 명, 쪽수, 활용 AI |

표시는 ✓ 외에 V·○·●도 읽습니다. 양식의 예시 행(`그림 OOOO`)은 건너뜁니다.

## 제작 방식별로 보는 것

| 제작 방식 | 필요한 것 | 대조 |
|---|---|---|
| 집필자 직접제작 | 양도 동의서(F07 붙임 4) | 제출 여부(집필자 단위 서류라 그림별 목록이 없음) |
| 외부 제작의뢰 | 제작 목록(F06 붙임 1), 제작자 양도 동의서(붙임 3) | 제작 목록에 그 그림이 있는지, 사진/삽화 구분이 같은지 |
| 포괄적 이용허락 | 이용허락 동의서(F07 붙임 3) | 동의서의 저작물 표에 그 그림이 있는지 |
| 공공누리·공유마당 | 낼 증빙 없음 | 원고에 출처 줄이 있는지, 공공누리·공유마당 표시가 보이는지 |
| 기개발 학습모듈 | 낼 증빙 없음 | 원고에 출처 줄이 있는지, 기존 학습모듈을 가리키는지 |
| 사진(직접·의뢰) | 인물이 있으면 초상권 동의서(F06 붙임 2) | 사람 확인 |
| AI 활용 | 원고의 AI 활용 줄, 서약서와 결과물 현황 | 원고 표기 ↔ 목록의 AI 칸 ↔ 결과물 현황(활용 AI, 쪽수 기재). 출력본 PDF가 있으면 쪽수가 맞는지도 |

## 판정

| 판정 | 뜻 | 예 |
|---|---|---|
| 부적합 | 서류로 확인되는 누락·불일치 | 목록에 없는 그림, 원고에 없는 목록 행, 필요한 증빙 없음, AI 표기와 목록이 다름, 기한 경과 |
| 판단불가 | 사람이 봐야 함 | 번호는 같고 제목이 다름, 제작 방식이 둘, 인물 포함 여부, 활용 AI 이름이 다름, 결과물 현황의 쪽수가 출력본과 다름, 수록 현황 목록이 없음 |
| 적합 | 위 둘이 없음 | |

- 제목은 띄어쓰기·기호 차이를 같은 것으로 봅니다.
- 수록 현황 목록이 없으면 제작 방식을 알 수 없어 모든 그림이 판단불가가 되고, 지적사항에는 '목록 미제출' 한 건으로 나옵니다.
- 제출 기한은 입력이 모자라도 항상 결과에 나옵니다(1차 검토일이 없으면 판단불가).
- 목록이 모듈별로 여러 개면 이 원고의 그림과 가장 많이 겹치는 목록으로 대조하고 그 사실을 안내에 적습니다.
- 원고의 그림과 서류의 행은 번호·제목이 모두 같은 것, 번호가 같은 것, 제목이 같은 것 순서로 짝짓습니다. 원고의 다른 그림과 꼭 맞는 행이나
  다른 그림의 번호가 붙은 행은 가져오지 않습니다(같은 제목의 그림이 다른 번호로 또 있거나 같은 번호가 두 번 쓰인 원고가 실제로 있습니다).
- 쪽수 대조: 결과물 현황에 적힌 쪽(‘p.12’, ‘pp. 12~13’) 가운데 하나가 출력본에서 그 그림 캡션이 놓인 쪽이면 맞는 것으로 봅니다.
  다르거나, 출력본에서 캡션·쪽 번호를 찾지 못하면 판단불가입니다(출력본의 줄 읽기는 어림이라 부적합으로 올리지 않습니다).

## 기관별 알림

지적마다 **받는 곳**이 붙습니다.

| 받는 곳 | 받는 지적 |
|---|---|
| 개발기관 | 서류를 내거나 원고·목록을 고쳐야 하는 것 — 목록 누락, 원고에 없음, 제작 방식 미표시·중복, 증빙 누락, 출처 미표기, AI 표기 누락·불일치, 현황 누락, 쪽수·일자 미기재, 목록 미제출, 기한 경과·미제출 |
| 에디팅 기관 | 같은 것인지 사람이 가려야 하는 것 — 제목·번호·유형이 다름, 출처 확인, 초상권 확인, 활용 AI 이름이 다름, 쪽수가 다름, 현황에만 있음, 날짜를 넣지 않아 기한을 계산하지 못함 |

결과의 `알림`에 받는 곳마다 건수와 **그대로 보낼 수 있는 글**이 들어 있습니다. 화면의 ‘기관별 알림’에서 [알림 글 복사]로 가져가고,
현황표 xlsx에는 `알림_개발기관`·`알림_에디팅 기관` 시트로 들어갑니다. 에디팅 기관의 글에는 개발기관에 보완을 요청한 건수가 함께 적힙니다.
**이 시스템이 메일·메신저로 직접 보내지는 않습니다.**

## 이미지 저작권 DB에 등록

데이터베이스가 연결되어 있으면 결과 아래의 [이미지 저작권 DB에 등록]으로:

1. 원고의 그림 파일, 수록 위치(모듈·그림 번호·그림명·출처 줄), 목록의 제작 방식(분류 체계), AI 표기를 이미지 레코드로 적재하고
2. 현황표에서 '제출'로 확인된 증빙(양도·이용허락·초상권 동의서, AI 서약서)을 그 그림에 잇습니다.

다시 반영해도 그림·증빙이 늘지 않고, 기관이 확정한 권리 정보는 바뀌지 않습니다. 원고가 hwpx여야 하고 모듈 코드가 필요합니다(파일 이름에 있으면 자동).
그림 파일은 캡션 바로 위(앞 캡션보다 아래, 8문단 안)에 놓인 것으로 짝짓습니다. 출력본 PDF를 함께 올렸으면 수록 위치에 쪽도 들어갑니다.

## 올린 서류의 보관 (REQ-04-002)

- 원고·서류·출력본은 점검하는 동안만 서버의 임시 폴더에 두고, 응답을 보내기 전에 지웁니다. 서류 파일과 그 본문은 서버에 남지 않습니다.
- 서류에서 읽는 것은 네 가지 표(수록 현황 목록, 제작 목록, 이용허락 동의서의 저작물 표, AI 결과물 현황)뿐입니다. 서명란·생년월일·주소가 있는 본문은 읽지 않습니다.
- 이미지 저작권 DB에 반영할 때 남는 것: 그림 파일, 수록 위치, 제작 방식, AI 표기, 그리고 증빙의 종류·**서류 파일 이름**·제출일.
  파일 이름에 사람 이름이 들어 있으면 그대로 남으므로, 반영 전에 파일 이름을 확인합니다.
- 생성형 AI로 보내는 것은 없습니다.

## 평가 (검증 기준)

`tests/eval_rights.py`가 누락을 심은 서류 묶음으로 정의서의 두 기준을 잽니다.

```bash
python tests/eval_rights.py 원고1.hwpx 원고2.hwpx --cases 20 --seed 555 --md 결과.md --json 결과.json
```

원고마다 모든 증빙이 갖춰진 서류 묶음을 만든 뒤, 사례마다 누락을 3~6가지 심습니다(목록에서 빼기, 목록에만 있는 행, 제작 방식 지우기,
제작 목록·이용허락 동의서·결과물 현황에서 빼기, 양도 동의서·서약서 미제출, 목록에만 AI 표시, 합성 원고에서는 출처 미표기와 AI 표기 불일치).
정답은 점검 코드가 아니라 심은 것에서 정합니다. 현황표의 한 줄(그림 한 개)의 부적합 지적 종류가 정답과 같으면 맞음, **오차율 = 틀린 줄 ÷ 전체 줄**.
판단불가는 채점하지 않습니다.

2026-11-17 측정 — 합성 원고 3권 + 실제 원고 3권(객실 예약 관리 51그림, AIoT 심의본 17그림, AIoT 1차 초안 27그림), 원고마다 22사례:

| 기준 | 결과 |
|---|---|
| 증빙 누락 탐지 오차율 5% 이내 | 고치기 전에도 기준 안이었다: 첫 측정 2,030줄 중 틀린 줄 3(0.15%), 결함 1을 고친 뒤 다른 seed 5개 14,715줄 중 틀린 줄 3(0.02%). 결함을 고친 뒤, 고치는 데 쓰지 않은 seed 3개(555, 31337, 8)로는 **8,815줄 중 틀린 줄 0** — 심은 누락 4,033건을 모두 찾았고 심지 않은 부적합은 0건 |
| 기한(4주) 경과 알림 누락 0건 | 12사례(제출일·점검일이 기한 −27일~+90일, 28일째·29일째 경계 포함) 중 경과 6건 — 알림 누락 0건, 잘못된 알림 0건 |

평가에서 나와 고친 결함(모두 실제 원고에서만 나옴. 2는 측정에 걸리지는 않았고 1을 고치며 코드에서 찾음):

1. 같은 제목의 그림이 다른 번호로 또 있으면(객실 예약 관리의 그림 1-10·1-13) 한쪽의 이용허락 동의서 행을 다른 쪽의 것으로 보아 누락을 놓침
2. 앞 그림이 목록에 없을 때 제목만 같은 뒤 그림의 행을 먼저 가져가 누락이 엉뚱한 그림에 붙을 수 있음
3. 뒤 번호가 빈 캡션의 제목이 숫자로 시작하면(‘그림 2- 6LoWPAN 프로토콜 스택’) 결과물 현황에서 6을 뒤 번호로 읽음

이 수치의 한계:

- 서류는 실제 제출본이 아니라 양식과 같은 칸 배치로 만든 것입니다. 표기는 흔들었지만(✓·V·○·●, 제목 띄어쓰기, 괄호 없는 번호) 실제 제출본의 변형을 다 담지 못합니다.
- 실제 원고의 그림 목록은 점검 코드와 같은 읽기에서 왔으므로 캡션을 못 읽은 그림은 평가에 잡히지 않습니다. 어림으로 ‘[그림 N-M]’으로 시작하는 문단 수와 견주면
  객실 예약 관리만 52 대 51로 하나 다르고, 그 하나는 메모 안의 글이라 빼는 것이 맞습니다.
- 정답을 만드는 규칙(`expected_row`)은 위 ‘제작 방식별로 보는 것’ 표를 옮긴 것입니다. 표 자체가 계약서 해석과 다르면 이 평가로는 드러나지 않습니다.

## 알려진 한계

- 받은 자료가 빈 양식이라, 양식의 예시 행과 같은 칸 배치로 만든 합성 서류로만 검증했습니다. 실제 제출본으로는 아직 돌려 보지 않았습니다.
- 쪽수는 출력본 PDF를 함께 올렸을 때만 대조합니다(한글 파일만으로는 그림이 몇 쪽에 있는지 알 수 없음). 없으면 결과물 현황의 쪽수는 기재 여부만 봅니다.
  실제 출력본 PDF로는 아직 돌려 보지 않았습니다 — 합성 출력본 1개로만 확인했습니다.
- 그림 캡션이 없는 그림은 목록과 맞출 수 없어 점검 대상에서 빠집니다.
- F08의 표기 예 2(집필진 삽화를 AI로 수정 보완)는 예시 문구가 '생성함'으로 적혀 있습니다. 원고의 표기만으로는 어느 예에 해당하는지 알 수 없으므로 '생성함'과 '수정 보완함'을 모두 그대로 읽고 맞고 틀림은 따지지 않습니다.
- 누락 알림은 받는 곳별 글과 xlsx 시트까지입니다. 개발기관·에디팅 기관에 직접 보내는 기능은 없습니다.
- 기한은 수록 현황 목록 한 건에 대해서만 봅니다. 1차 검토일과 제출일은 사람이 입력합니다.
- 캡션 하나에 그림 파일이 여럿이면((좌)·(우)) 이미지 저작권 DB에는 캡션에 가장 가까운 그림 하나만 들어갑니다.
