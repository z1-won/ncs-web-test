# 권리 증빙 제출 현황 점검 (REQ-02-014)

원고의 그림과 제출 서류를 대조해 빠진 권리 증빙을 찾습니다. 기준은 「NCS PoC 과업 안내」(요구사항정의서 V0.23) REQ-02-014,
원고 집필 계약서(F07), 사진·삽화 제작 계약서(F06), AI 도구 사용 표기 예(F08), 생성형 AI 결과물 집필자 서약서(F09)입니다.
코드는 `ncs_rights`(서류 읽기·대조), `ncs_core/figures.py`(원고의 그림 읽기), `ncs_service/rights_link.py`(이미지 저작권 DB 연결).

## 쓰는 법

화면: 메뉴의 **권리 증빙 점검**(`/rights`). 데이터베이스 없이도 됩니다.

```bash
python -m ncs_rights 원고.hwpx 계약서붙임.hwp 제작목록.hwp 서약서.hwpx \
    --first-review 2026-10-01 --submitted 2026-10-20 --transfer-author --transfer-maker --pledge --portrait none --xlsx 현황표.xlsx
```

## 입력

| 입력 | 내용 |
|---|---|
| 원고 | hwpx 또는 hwp. 그림 캡션 `[그림 N-M] 그림명`과 그 위의 `출처:` 줄, AI 활용 줄을 읽음 |
| 제출 서류 | 작성한 한글 양식(hwp·hwpx) 여러 개. **파일 이름과 무관하게 안에 든 표의 머리 글로 양식을 알아봄** — 계약서 한 파일에 붙임이 여러 개 있어도 됨 |
| 1차 검토일, 제출일 | 수록 현황 목록의 제출 기한(1차 검토 이후 4주, 원고 집필 계약서 제5조 1항) 계산용 |
| 서명 서류 제출 여부 | 집필자 양도 동의서, 제작자 양도 동의서, AI 서약서 — 표가 아니라 서명 문서라 파일에서 읽지 못해 직접 표시 |
| 초상권 | 확인하지 않음 / 인물이 든 사진 없음 / 동의서 제출됨. 인물 포함 여부는 그림을 봐야 알므로 자동 판정하지 않음 |

읽는 표:

| 양식 | 알아보는 머리 글 | 읽는 것 |
|---|---|---|
| 사진·삽화 수록 현황 목록 (F07 붙임 2) | 시각적 자료 제목, 저작물 제작 방식 | 그림 번호·제목, ✓가 놓인 제작 방식 칸(사진/삽화 구분 포함), 학습모듈명 |
| 사진·삽화 제작 목록 (F06 붙임 1) | 저작물명, 자료 유형 | 그림 번호·제목, 사진/삽화 |
| 지식재산권 이용허락 동의서 (F07 붙임 3) | 저작물 제목, 출처 | 저작물 제목, 출처, 활용 학습모듈명 |
| 생성형 AI 결과물 현황 (F09 붙임) | 결과물 명, 활용 AI | 결과물 명, 쪽수, 활용 AI |

표시는 ✓ 외에 V·○·●도 읽습니다. 양식의 예시 행(`그림 OOOO`)은 건너뜁니다.

## 제작 방식별로 보는 것

| 제작 방식 | 필요한 것 | 대조 |
|---|---|---|
| 집필자 직접제작 | 양도 동의서(F07 붙임 4) | 제출 여부(집필자 단위 서류라 그림별 목록이 없음) |
| 외부 제작의뢰 | 제작 목록(F06 붙임 1), 제작자 양도 동의서(붙임 3) | 제작 목록에 그 그림이 있는지, 사진/삽화 구분이 같은지 |
| 포괄적 이용허락 | 이용허락 동의서(F07 붙임 3) | 동의서의 저작물 표에 그 그림이 있는지 |
| 공공누리·공유마당 | 낼 증빙 없음 | 원고에 출처 줄이 있는지, 공공누리·공유마당 표시가 보이는지 |
| 기개발 학습모듈 | 낼 증빙 없음 | 원고에 출처 줄이 있는지, 기존 학습모듈을 가리키는지 |
| 사진(직접·의뢰) | 인물이 있으면 초상권 동의서(F06 붙임 2) | 사람 확인 |
| AI 활용 | 원고의 AI 활용 줄, 서약서와 결과물 현황 | 원고 표기 ↔ 목록의 AI 칸 ↔ 결과물 현황(활용 AI, 쪽수 기재) |

## 판정

| 판정 | 뜻 | 예 |
|---|---|---|
| 부적합 | 서류로 확인되는 누락·불일치 | 목록에 없는 그림, 원고에 없는 목록 행, 필요한 증빙 없음, AI 표기와 목록이 다름, 기한 경과 |
| 판단불가 | 사람이 봐야 함 | 번호는 같고 제목이 다름, 제작 방식이 둘, 인물 포함 여부, 활용 AI 이름이 다름, 수록 현황 목록이 없음 |
| 적합 | 위 둘이 없음 | |

- 제목은 띄어쓰기·기호 차이를 같은 것으로 봅니다.
- 수록 현황 목록이 없으면 제작 방식을 알 수 없어 모든 그림이 판단불가가 되고, 지적사항에는 '목록 미제출' 한 건으로 나옵니다.
- 제출 기한은 입력이 모자라도 항상 결과에 나옵니다(1차 검토일이 없으면 판단불가).
- 목록이 모듈별로 여러 개면 이 원고의 그림과 가장 많이 겹치는 목록으로 대조하고 그 사실을 안내에 적습니다.

## 이미지 저작권 DB에 반영

데이터베이스가 연결되어 있으면 결과 아래의 [이미지 저작권 DB에 반영]으로:

1. 원고의 그림 파일, 수록 위치(모듈·그림 번호·그림명·출처 줄), 목록의 제작 방식(분류 체계), AI 표기를 이미지 레코드로 적재하고
2. 현황표에서 '제출'로 확인된 증빙(양도·이용허락·초상권 동의서, AI 서약서)을 그 그림에 잇습니다.

다시 반영해도 그림·증빙이 늘지 않고, 기관이 확정한 권리 정보는 바뀌지 않습니다. 원고가 hwpx여야 하고 모듈 코드가 필요합니다(파일 이름에 있으면 자동).

## 알려진 한계

- 받은 자료가 빈 양식이라, 양식의 예시 행과 같은 칸 배치로 만든 합성 서류로만 검증했습니다. 실제 제출본으로는 아직 돌려 보지 않았습니다.
- 쪽수는 대조하지 않습니다(한글 파일만으로는 그림이 몇 쪽에 있는지 알 수 없음). 결과물 현황의 쪽수는 기재 여부만 봅니다.
- 그림 캡션이 없는 그림은 목록과 맞출 수 없어 점검 대상에서 빠집니다.
- F08의 표기 예 2(집필진 삽화를 AI로 수정 보완)는 예시 문구가 '생성함'으로 적혀 있습니다. 원고의 표기만으로는 어느 예에 해당하는지 알 수 없으므로 '생성함'과 '수정 보완함'을 모두 그대로 읽고 맞고 틀림은 따지지 않습니다.
- 누락 알림은 화면과 xlsx로만 보여 줍니다. 개발기관·에디팅 기관에 따로 보내는 기능은 없습니다.
