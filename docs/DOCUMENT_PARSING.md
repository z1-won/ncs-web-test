# 규칙 기반 문서 구조 탐지 실험

작업 브랜치: `jiwon/doc-parse-test`. AI 호출이나 외부 의존성 없이 본문 경계 탐지를 개선한다.

## 책임 분리

- `ncs_core/documents.py`: HWP/HWPX 읽기와 `Document` 모델. 로드 후 정규화를 호출한다.
- `ncs_core/manuscript/structure.py`: 차례·본문 경계 탐지와 구역 정규화. 파일 I/O·검수 판정은 하지 않는다.
- `documents.py`의 기존 `body_start`, `toc_title_index`, `toc_section`, `normalize_sections`,
  `split_single_section` 호출은 호환 래퍼로 유지한다.
- `detect_body_boundary(document)`는 원본 구역·문단 번호와 근거를 담은 `BodyBoundary` 또는 `None`을 반환한다.
  정규화 전 문서에 호출해야 원본 위치를 얻는다. UI 진단 연결은 이번 변경에 포함하지 않는다.

## 탐지 규칙

기존 양식의 개요 종료 표식과 큰학습 스타일을 유지하면서, 추가로 다음 조합을 검사한다.

1. 표 셀·메모 밖의 `학습 N` 후보를 찾는다.
2. 뒤의 최대 80문단 안에서 내비게이터 번호와 연결되는 `N-M.` 하위 제목을 찾는다.
3. 하위 제목 다음에서 학습 목표, 필요 지식, 수행 내용 또는 학습 목표 표를 확인한다.
   다음 학습·하위 제목·평가를 넘어서 근거를 가져오지 않는다.
4. 차례가 있는 구역부터 이후 구역을 모두 탐색한다. 차례의 학습명 일치는 필수 조건으로 두지 않는다.
5. 경계가 확인되면 앞부분과 본문을 각각 한 구역으로 합친다. 원문 텍스트와 문단 연결 메타데이터를 유지한다.

근거가 부족하면 원본 배치를 유지한다. 탐지 실패를 필수 항목 누락이나 부적합으로 새로 판정하지 않는다.
기존 검수 엔진의 판단불가 처리 정책은 변경하지 않는다.

## 검증과 한계

`tests/test_structure_detection.py`는 스타일·개요 종료 표식 누락, 표의 목표,
본문 시작 구역 이동, 본문 여러 구역 분할, 차례 이름 불일치, 메모·표 오인식,
번호 불일치, 평가에서 목표를 잘못 가져오는 경우를 합성 `Document`로 검증한다.
기존 `test_layouts.py`, `test_single_section.py`, 골든 테스트도 유지한다. 골든 정답은 재생성하지 않는다.

실제 신규 실패 원본은 제공되지 않아, 이번 검증은 실문서 일반화 성능을 입증하지 않는다.
`제1학습` 등 다른 제목 문법, 학습 제목과 하위 제목이 서로 다른 물리 구역에 있는 경우,
앞부분이 전혀 없는 원고, 개발계획서 병합 셀 해석 개선은 지원 범위에 추가하지 않았다.
HWP는 로더가 제공하지 않는 스타일·표 내부 문단·메모 정보를 활용할 수 없다.
후속 작업은 실제 실패 원본을 확보해 구조 정답을 표시하고 양식 계열별로 평가하는 것이다.

전체 테스트의 `test_web_server_and_frontend_list_every_engine`은 변경 전 HEAD에서도 실패한다.
프런트엔드 목록이 `App.jsx`에서 `lib/checks.js`로 분리됐지만 테스트가 이전 파일의 리터럴을 찾기 때문이다.
이 파서 작업에서는 해당 프런트엔드 계약 테스트를 수정하지 않는다.
