# 이미지 추천 (REQ-02-011)

집필 중인 문단과 수행준거를 넣으면 이미지 저작권 DB(REQ-02-010)에서 실을 수 있는 그림을 권한다.
화면은 메뉴의 **이미지 추천**(`/recommend`), API는 `POST /api/recommend/images`. 데이터베이스(PostgreSQL)가 있어야 한다.

## 흐름

1. **문맥 읽기** (`ncs_recommend/context.py`) — 문단과 수행준거 글에서 요약과 핵심어를 뽑는다.
   - 생성형 AI를 쓸 수 있으면(아래) 문단을 보내 요약 1~2문장과 핵심어 3~8개를 받는다.
   - AI가 낸 핵심어 가운데 **입력 글에 실제로 있는 낱말만** 쓴다. 글에 없는 말은 버리고 화면에 따로 보여 준다.
   - AI를 쓸 수 없거나 실패하면 규칙으로 핵심어만 뽑는다(조사를 떼고 자주 나온 낱말 순. 형태소 분석이 아니라 어림이다). 요약은 없다.
   - 어느 쪽으로 했는지는 결과의 `context.method`(`llm` / `rule`)와 화면의 배지로 보인다.
2. **후보** (`ncs_service/image_recommend.py`) — `v_image_recommendable` 뷰에서 비공개를 뺀 것만 꺼낸다.
   기관이 확정하지 않았거나 재사용 범위가 미확인인 그림은 어떤 입력으로도 나오지 않는다.
3. **순위** (`ncs_recommend/rank.py`) — 아래 점수로 줄을 세운다. 핵심어도 수행준거 연결도 맞지 않는 그림은 추천하지 않는다.

| 근거 | 점수 |
|---|---|
| 핵심어가 그림의 키워드에 있음 | 3 |
| 핵심어가 제목·캡션에 있음 | 2 |
| 핵심어가 그림 사용 문장에 있음 | 1 |
| (핵심어마다 가장 높은 것 하나. 앞 순위 핵심어일수록 ×1.0 … ×0.6) | |
| 같은 능력단위에 이어진 그림 | 2 |
| 같은 능력단위요소 | 3 |
| 같은 수행준거 | 6 |
| 정부 귀속 + 전체 재사용 자산 | +1 |

정부 귀속 가산은 1점이다. 비슷하게 맞는 그림 가운데서는 정부 귀속 자산이 앞에 오지만, 관련이 훨씬 높은 다른 그림을 밀어내지는 않는다.
점수의 크기는 PoC에서 정한 값이며 정답 세트로 Recall@k·nDCG를 재면서 조정할 대상이다(아직 재지 않았다).

## 그림마다 함께 보여 주는 것

- **범위 확인 필요** — 이용허락 한정 자산이거나 재사용 범위가 '해당 학습모듈 한정'인 그림
- **라이선스·이용조건** — 공공누리 유형, 출처표시·상업적 이용금지·변경금지
- **AI유형 안내** — AI유형이 함께 표시돼도 원고 수록에는 제1~4유형 조건이 그대로 적용된다는 안내
- **제0유형 안내** — 공공누리상 출처표시 의무는 없지만 계약서 제4조에 따라 원고에는 출처를 적는다는 안내
- **출처 문구** — DB의 출처 문구 앞에 `출처: `를 붙인 것. [복사] 단추로 가져간다.
  공공누리인데 출처 문구가 비어 있으면 URL·검색일·유형으로 만든다. 그 밖의 그림은 DB에 문구가 없으면 만들지 않고 채우라고 안내한다.
- **화질** — 300dpi로 실을 수 있는 가로 길이(mm). 40mm 미만이면 '화질 낮음'. 업스케일본이 있으면 그 크기로 본다.

추천할 그림이 없거나 모두 화질이 낮으면 생성형 AI 생성·수정 보완(REQ-02-006)으로 안내하고, AI 활용 표기와 결과물 현황 등록을 함께 알린다.

## 생성형 AI 설정

`ncs_core.llm`을 그대로 쓴다. 키(`LLM_API_KEY` 또는 `OPENAI_API_KEY`)와 원고 외부 전송 승인(`LLM_ALLOW_UPLOAD=1`)이 **둘 다** 있어야 부른다.

| 환경 변수 | 뜻 |
|---|---|
| `LLM_MODEL` | 모든 LLM 작업의 모델(기본 `gpt-5.4-mini`) |
| `LLM_MODEL_RECOMMEND` | 이미지 추천에만 쓸 모델. 없으면 `LLM_MODEL` |
| `LLM_ALLOWED_TASKS` | 적으면 그 작업만 허용. 추천의 작업 이름은 `image_recommend_context` |

보내는 것은 화면에 넣은 문단(4,000자까지)과 수행준거 글뿐이다. 응답은 `.llm_cache/image_recommend_context/`에 캐시되고(문단이 평문으로 들어 있음,
`LLM_CACHE_TTL_DAYS` 뒤 삭제) 토큰 수는 `usage.jsonl`에 남는다. 화면의 체크를 끄거나 API에 `use_llm: false`를 주면 보내지 않는다.

## API

```
POST /api/recommend/images
{ "text": "문단", "unit_code": "LM1203020201", "criterion_no": "1.1", "limit": 10, "use_llm": true }
```

`text`와 `unit_code` 중 하나는 있어야 한다. 응답:

- `context` — `summary`, `keywords`, `method`, `model`, `note`, `dropped`
- `criterion` — 넣은 능력단위·수행준거와 NCS 목록에서 찾은 글
- `items` — 추천 그림. 권리·출처 정보와 `score`, `matched`, `link_level`, `priority`, `scope_check_needed`, `conditions`, `notes`, `credit`, `max_width_mm`, `low_quality`
- `guidance` — 추천이 없거나 화질이 낮을 때의 안내
- 그림 파일은 `GET /api/images/recommendable/{id}/file`

## 하지 않는 것

- **출처 표기 자동 삽입** — 집필 화면(원고 편집기)이 이 시스템에 없어 원고에 직접 넣지 못한다. 출처 문구를 만들어 복사하게 하는 데까지다.
- **그림의 내용 이해** — 그림 자체를 보지 않는다. DB에 적힌 키워드·제목·캡션·수행준거 연결로만 찾는다. 메타데이터가 빈 그림은 추천되지 않는다.
- **의미 검색(임베딩)** — 낱말이 달라도 뜻이 같은 것은 찾지 못한다('프런트' ↔ '접수대').
- **검증 수치** — Recall@k·nDCG, 요약 충실도 85%, 집필자 Likert는 아직 재지 않았다. 확정된 그림과 정답 세트가 있어야 한다.
