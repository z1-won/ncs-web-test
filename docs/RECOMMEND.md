# 이미지 추천 (REQ-02-011)

집필 중인 문단과 수행준거를 넣으면 이미지 저작권 DB(REQ-02-010)에서 실을 수 있는 그림을 권한다.
화면은 메뉴의 **이미지 추천**(`/recommend`), API는 `POST /api/recommend/images`. 데이터베이스(PostgreSQL)가 있어야 한다.

## 흐름

1. **문맥 읽기** (`ncs_recommend/context.py`) — 문단과 수행준거 글에서 요약과 핵심어를 뽑는다.
   - 생성형 AI를 쓸 수 있으면(아래) 문단을 보내 요약 1~2문장과 핵심어 3~8개를 받는다.
   - AI가 낸 핵심어 가운데 **입력 글에 실제로 있는 낱말만** 쓴다. 글에 없는 말은 버리고 화면에 따로 보여 준다.
   - AI를 쓸 수 없거나 실패하면 규칙으로 핵심어만 뽑는다(조사를 떼고 자주 나온 낱말 순. 형태소 분석이 아니라 어림이다). 요약은 없다.
   - 어느 쪽으로 했는지는 결과의 `context.method`(`llm` / `rule`)와 화면의 배지로 보인다.
2. **후보** (`ncs_service/image_recommend.py`) — `v_image_recommendable` 뷰에서 비공개를 뺀 것만 꺼낸다.
   기관이 확정하지 않았거나 재사용 범위가 미확인인 그림은 어떤 입력으로도 나오지 않는다.
3. **그림 유사도** (`ncs_recommend/embed.py`, 켜져 있을 때) — 문맥(요약 또는 핵심어)과 그림 자체를 같은 임베딩 모델로 벡터로 바꿔 견준다.
   그림에 키워드를 달아 두지 않았어도, 낱말이 달라도 그림이 문맥과 닮았으면 찾는다. **이 컴퓨터에서 계산하며 외부로 보내지 않는다**(아래 ‘그림 임베딩’).
4. **순위** (`ncs_recommend/rank.py`) — 아래 점수로 줄을 세운다.

| 근거 | 점수 |
|---|---|
| 핵심어가 그림의 키워드에 있음 | 3 |
| 핵심어가 제목·캡션에 있음 | 2 |
| 핵심어가 그림 사용 문장에 있음 | 1 |
| (핵심어마다 가장 높은 것 하나. 앞 순위 핵심어일수록 ×1.0 … ×0.6) | |
| 같은 능력단위에 이어진 그림 | 1 |
| 같은 능력단위요소 | 2 |
| 같은 수행준거 | 3 |
| 후보 대부분(80% 이상, 후보 8장부터)에 맞는 핵심어 | 위 점수의 1/4 |
| 그림 유사도 — 바탕을 뺀 값(σ 1.5 이하 0, 3.0 이상 1) × 6 | 0 ~ 6 |
| 정부 귀속 + 전체 재사용 자산 | +1 |

핵심어도 수행준거 연결도 맞지 않는 그림은, 그림 유사도가 뚜렷이 높을 때(유사도 점수 0.5 이상, σ 2.25부터)만 추천한다.

**그림 유사도를 재는 법.** 코사인 유사도에서 두 가지 바탕을 빼고 한 가지 단위로 나눈 값(σ)으로 본다.

- **그림의 바탕** — 그 그림이 서로 다른 분야의 글 24개(`embed.REFERENCE_TEXTS`)와 닮은 정도의 중앙값. 무슨 글에나 닮게 나오는 그림을 거른다.
- **글의 바탕** — 후보들(5장부터)의 위 값의 중앙값, 0보다 클 때만. 후보 대부분에 고르게 닮는 글을 거른다
  ('호텔 경영 전략을 수립한다'는 호텔 사진 모두와 조금씩 닮지만 어느 그림도 가리키지 않는다).
- **단위** — 후보 그림들의 바탕 퍼짐(MAD)의 중앙값. 모델마다 유사도 크기가 달라도 같은 문턱을 쓰기 위한 것이다.

σ 1.5 이하는 0, 3.0 이상은 1. 맞는 그림이 하나도 없으면 아무도 점수를 받지 않는다.

2026-11-20 측정 — SigLIP 2(`so400m-patch16-256`), 공공누리 호텔 사진 8장, 점검 문장 29개(맞는 그림이 있는 글 21, 없는 글 8).
`scripts/probe/embed_probe.py --dump`로 남긴 벡터로 계산했다.

| 방식 | 1위 정확 | 유사도만으로 추천(50%)될 때 |
|---|---|---|
| 코사인 유사도 그대로 | 19/21 | (문턱을 정할 수 없음 — 무관한 글의 최고값 0.116이 맞는 쌍의 중앙값 0.132에 가깝다) |
| 그림마다 제 퍼짐으로 나눈 z(처음 넣은 식) | 19/21 | 순서가 뒤집히는 경우가 있어 버렸다 |
| 지금 식 | 20/21 | 맞는 쌍 20/28, 무관한 글 오탐 0/64, 틀린 그림 오탐 2/140 |

이 수치의 한계: **문턱을 맞춘 자료와 잰 자료가 같다.** 그림은 한 호텔의 사진 8장뿐이고 도해·흐름도는 없다.
다른 그림·다른 모델에서는 다시 재야 한다. 또 긴 문장은 짧은 묘사보다 가려내는 힘이 약하다
(프런트 데스크 사진: 긴 문장 2.4σ 대 2위 2.1σ, '접수대' 한 낱말 3.2σ 대 2위 0.8σ) — 견줄 글을 어떻게 만들지는 남은 일이다.
글의 바탕은 후보끼리 견주는 것이라, 후보가 모두 같은 장면이고 글도 그 장면이면 아무도 점수를 받지 못한다(그때는 핵심어로 찾는다).

**흔한 핵심어.** 후보 대부분에 맞는 핵심어는 그림을 가려 주지 못한다(같은 호텔 사진 8장에 '호텔'). 점수를 1/4만 치고,
그것만 맞은 그림은 추천하지 않는다. 다만 그래서 추천이 하나도 없으면 그 그림들을 그대로 보여 준다.
수행준거 연결은 가산점일 뿐이다 — 연결해 둔 그림만 나오지 않게 점수를 낮게 두었다.

정부 귀속 가산은 1점이다. 비슷하게 맞는 그림 가운데서는 정부 귀속 자산이 앞에 오지만, 관련이 훨씬 높은 다른 그림을 밀어내지는 않는다.
점수의 크기는 PoC에서 정한 값이며 정답 세트로 Recall@k·nDCG를 재면서 조정할 대상이다(아직 재지 않았다).

## 그림마다 함께 보여 주는 것

- **범위 확인 필요** — 이용허락 한정 자산이거나 재사용 범위가 '해당 학습모듈 한정'인 그림
- **라이선스·이용조건** — 공공누리 유형, 출처표시·상업적 이용금지·변경금지
- **AI유형 안내** — AI유형이 함께 표시돼도 원고 수록에는 제1~4유형 조건이 그대로 적용된다는 안내
- **제0유형 안내** — 공공누리상 출처표시 의무는 없지만 계약서 제4조에 따라 원고에는 출처를 적는다는 안내
- **출처 문구** — DB의 출처 문구 앞에 `출처: `를 붙인 것. [복사] 단추로 가져간다.
  공공누리인데 출처 문구가 비어 있으면 URL·검색일·유형으로 만든다. 그 밖의 그림은 DB에 문구가 없으면 만들지 않고 채우라고 안내한다.
- **화질** — 300dpi로 실을 수 있는 가로 길이(mm). 40mm 미만이면 '화질 낮음'. 업스케일본이 있으면 그 크기로 본다.

추천할 그림이 없거나 모두 화질이 낮으면 생성형 AI 생성·수정 보완(REQ-02-006)으로 안내하고, AI 활용 표기와 결과물 현황 등록을 함께 알린다.

## 그림 임베딩 (외부 전송 없음)

공개된 이미지-글 임베딩 모델을 **이 컴퓨터에서 직접** 돌린다. 그림도 문단도 밖으로 나가지 않는다. 모델을 새로 학습하지 않는다.

설치와 켜기:

```
pip install -e ".[embed]"
```

`.env`에 모델 이름을 적으면 켜진다. 비어 있으면 꺼져 있고 추천은 핵심어·수행준거로만 한다.

| 환경 변수 | 뜻 |
|---|---|
| `NCS_EMBED_MODEL` | 모델 이름. 권장 `google/siglip2-base-patch16-224`(Apache 2.0, 다국어). 비우면 꺼짐 |
| `NCS_EMBED_DEVICE` | `cpu`(기본) / `mps`(Apple Silicon) / `cuda` |
| `HF_HUB_OFFLINE` | 모델을 한 번 내려받은 뒤 `1`로 두면 네트워크를 전혀 쓰지 않는다 |

모델 파일은 처음 쓸 때 허깅페이스에서 한 번 내려받는다(이때만 네트워크를 쓴다. 보내는 것은 없다).
그림 벡터는 적재할 때 자동으로 계산해 `image_embeddings` 표에 둔다(그림마다 모델별 한 벌, 업스케일본이 있으면 그것으로).
이미 들어 있는 그림이나 모델을 바꾼 뒤에는 한꺼번에 채운다.

```
python -m ncs_service.image_embed            # 벡터가 없는 그림 모두
python -m ncs_service.image_embed --status   # 채워진 개수만
python scripts/probe/embed_probe.py          # 모델이 올라오는지, 한국어 글과 그림이 맞는지 간단히 보기
```

알아 둘 점:

- 모델의 글 길이 상한이 짧아(64토큰) 문단을 통째로 넣지 않고 AI 요약(없으면 핵심어)을 넣는다.
- 한국어 전문 용어 문단에서 얼마나 잘 맞는지는 **재 보지 않았다**. 그래서 핵심어·수행준거 점수를 버리지 않고 더해서 쓴다.
- 모델을 올리는 데 메모리(수백 MB~수 GB)와 시간이 든다. 서버를 띄운 뒤 처음 추천·적재할 때 한 번 느리다.
- 모델을 바꾸면 벡터를 다시 계산해야 한다(옛 모델의 벡터는 남아 있어도 쓰지 않는다).

## 생성형 AI 설정

`ncs_core.llm`을 그대로 쓴다. 키(`LLM_API_KEY` 또는 `OPENAI_API_KEY`)와 원고 외부 전송 승인(`LLM_ALLOW_UPLOAD=1`)이 **둘 다** 있어야 부른다.

| 환경 변수 | 뜻 |
|---|---|
| `LLM_MODEL` | 모든 LLM 작업의 모델(기본 `gpt-5.4-mini`) |
| `LLM_MODEL_RECOMMEND` | 이미지 추천에만 쓸 모델. 없으면 `LLM_MODEL` |
| `LLM_ALLOWED_TASKS` | 적으면 그 작업만 허용. 추천의 작업 이름은 `image_recommend_context` |

보내는 것은 화면에 넣은 문단(4,000자까지)과 수행준거 글뿐이다. 응답은 `.llm_cache/image_recommend_context/`에 캐시되고(문단이 평문으로 들어 있음,
`LLM_CACHE_TTL_DAYS` 뒤 삭제) 토큰 수는 `usage.jsonl`에 남는다. 화면의 체크를 끄거나 API에 `use_llm: false`를 주면 보내지 않는다.

## API

```
POST /api/recommend/images
{ "text": "문단", "unit_code": "LM1203020201", "criterion_no": "1.1", "limit": 10, "use_llm": true }
```

`text`와 `unit_code` 중 하나는 있어야 한다. 응답:

- `context` — `summary`, `keywords`, `method`, `model`, `note`, `dropped`
- `embedding` — `used`, `model`, `query`(그림과 견준 글), `covered`(벡터가 있는 후보 수), `note`
- `criterion` — 넣은 능력단위·수행준거와 NCS 목록에서 찾은 글
- `items` — 추천 그림. 권리·출처 정보와 `score`, `matched`, `link_level`, `similarity`, `visual`, `priority`, `scope_check_needed`, `conditions`, `notes`, `credit`, `max_width_mm`, `low_quality`
- `guidance` — 추천이 없거나 화질이 낮을 때의 안내
- 그림 파일은 `GET /api/images/recommendable/{id}/file`

## 하지 않는 것

- **출처 표기 자동 삽입** — 집필 화면(원고 편집기)이 이 시스템에 없어 원고에 직접 넣지 못한다. 출처 문구를 만들어 복사하게 하는 데까지다.
- **그림 임베딩이 꺼져 있을 때** — 그림 자체를 보지 않고 DB에 적힌 키워드·제목·캡션·수행준거 연결로만 찾는다. 낱말이 달라도 뜻이 같은 것('프런트' ↔ '접수대')은 찾지 못한다.
- **그림 설명 자동 생성** — 그림을 보고 설명·키워드를 써 주지는 않는다(벡터로 견줄 뿐이다).
- **검증 수치** — Recall@k·nDCG, 요약 충실도 85%, 집필자 Likert는 아직 재지 않았다. 확정된 그림과 정답 세트가 있어야 한다.
