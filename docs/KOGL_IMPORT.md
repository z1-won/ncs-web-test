# 공공누리 수집 JSON 적재 (REQ-02-012)

공공누리에서 모은 그림을 과업 안내의 입력 형식(`schema_version: "0.1-PoC"`) 그대로 이미지 저작권 DB(REQ-02-010)에 넣는다.
수집표를 따로 만들지 않는다. 이 JSON 1개와 그림 파일들이 입력의 전부다.

구현은 `ncs_service/kogl_import.py`. 수집 JSON의 항목을 이미지 레코드([IMAGE_RECORD.md](IMAGE_RECORD.md))로 바꾼 뒤
레코드 적재(`ncs_service/image_db.py`)에 넘기므로, 중복 처리·확정 보호·이력은 레코드 적재와 같다.

## 쓰는 법

화면: **이미지 저작권 DB → 자료 적재**에서 수집 JSON 1개와 그림 파일들을 함께 고른다. 형식은 자동으로 알아본다
(`schema_version`이 `0.1-PoC`이고 `items`가 있으면 공공누리 수집 JSON). ‘형식만 검사’로 먼저 확인할 수 있다.

명령줄(그림은 JSON과 같은 폴더에 둔다):

```
python -m ncs_service.image_db 수집.json --check
python -m ncs_service.image_db 수집.json --by 이름
```

예시: `docs/examples/kogl_samples/`(JSON 1개 + 그림 1장. 그림과 기관명은 형식 확인용으로 만든 것이며 실제 공공누리 자료가 아니다).

## 항목이 어떻게 들어가는가

| 수집 JSON | 이미지 저작권 DB | 비고 |
|---|---|---|
| `image_id` | 수집 번호(`source_id`) | 화면에서 검색됨. 같은 그림인지는 파일의 SHA-256으로 가린다 |
| `title` | 자료 제목 | |
| `file.name` | 그림 파일(파일 자체를 저장) | **필수.** 함께 올린 파일에서 이름으로 찾는다. 폴더 경로는 떼고 이름만 쓴다 |
| `file.format`·`width_px`·`height_px` | 파일에서 직접 읽은 값 | 적힌 값과 다르면 안내만 하고 파일 값을 쓴다 |
| `ncs_link.lm_code` | 능력단위 코드 | `LM` + 숫자 10자리(+`_24v3`). NCS 목록에 있으면 버전까지 붙인다 |
| `ncs_link.element`·`performance_criteria` | 능력단위요소 코드·수행준거 번호 | NCS의 글과 같을 때만(띄어쓰기·문장부호 차이는 무시). 다르면 요소까지, 그것도 다르면 능력단위까지만 잇고 안내 |
| `ncs_link.match_keywords` | 주요 키워드 | |
| `kogl.type` | 공공누리 유형 0~4 | **필수.** `제1유형`, `1`, `3유형` 모두 읽는다 |
| `kogl.ai_type_combined` | AI유형 병행 | 제1~4유형과만 함께 쓸 수 있다 |
| `kogl.conditions` | 출처표시·상업적 이용금지·변경금지 | 유형에서 정해지는 값이다. 적었는데 유형과 다르면 **거부** |
| `source.original_org` | 원 출처 기관 | **필수** |
| `source.original_url` | 원 출처 URL | **필수.** http(s) 주소. 공공누리(kogl.or.kr·kogl.go.kr) 주소가 아니면 안내 |
| `source.retrieved_at` | 검색일 | **필수.** `YYYY-MM-DD` |
| `source.credit_line` | 출처 문구 | 적힌 값을 쓰지 않고 URL·검색일·유형으로 **만든다**(아래) |
| `status.confirmed_by` | — | 쓰지 않는다. 적재분은 항상 ‘자동’이고 확정은 화면에서 한다 |
| `status.tagging`·`db_target` | — | 쓰지 않는다 |

자동으로 채우는 권리 정보: 분류 체계 = 공공누리·CC(`public_license`), 지식재산권 귀속 = 공공누리(`kogl`),
제2~4유형은 산출물 분류 = 원 유형 승계(`inherit`). **재사용 범위는 채우지 않는다** — 기관이 확정 화면에서 정한다.

### 출처 문구

F14의 전자 자료 출처 형식으로 만든다.

```
공공누리 홈페이지(https://www.kogl.or.kr/…)에서 2026. 11. 17. 검색. 공공누리 제1유형.
```

적힌 `credit_line`이 이것과 다르면 만든 문구를 넣고 그 사실을 안내한다.
이 문구는 필요 지식 ⑧의 출처 골격 검사(`ncs_knowledge.rules.sources.source_check`)를 통과한다(테스트로 확인).

## 거부와 안내

거부(그 항목은 넣지 않는다. 다른 항목은 계속 넣는다):

- 그림 파일이 함께 올라오지 않음, 지원하지 않는 그림 형식
- 유형이 제0~4유형이 아님, 조건이 유형과 다름, 제0유형에 AI유형 병행
- 원 출처 기관·URL·검색일이 없거나 형식이 다름
- `lm_code` 형식이 다름, `match_keywords`가 문자열 목록이 아님
- 예시의 자리표시가 그대로 남음 — `(예시)`로 시작하는 제목, `(해당 자료 URL)` 같은 값

안내(넣기는 하되 확인할 점): 수행준거를 어디까지 이었는지, 파일에서 읽은 값과 적힌 값의 차이,
공공누리가 아닌 주소, 바꿔 넣은 출처 문구, 쓰지 않은 `confirmed_by`.

보고서의 ‘거부’·‘안내’에 나오는 순번은 수집 JSON `items`의 순번이다.

## 다시 넣으면

같은 파일(SHA-256)은 한 건으로 합친다. 비어 있던 값만 채우고, 기관이 확정한 권리 정보는 바꾸지 않는다
(보고서의 ‘확정이라 유지한 권리 정보’). 수행준거 연결은 없던 것만 더한다.

## 추천에 나오려면

적재분은 ‘자동’ 상태라 추천용 조회(`/api/images/recommendable`)에 나오지 않는다.
화면에서 재사용 범위를 정하고 **확정**해야 나온다. 수집과 확정을 나눈 것은 자동 태깅 결과를 사람이 한 번 보도록 하기 위해서다.

## 하지 않는 것

- 공공누리 사이트에서 자동으로 모으지 않는다. 수집(검색·내려받기·JSON 작성)은 사람이 한다.
- 원 출처 URL에 실제로 그 그림이 있는지, 적힌 유형이 사이트의 표시와 같은지는 확인하지 않는다.
- 그림의 내용과 수행준거가 맞는지는 판단하지 않는다(REQ-02-011 추천의 일).
